# OmniTAK Radio: upstream technical assessment

Baseline: [`engindearing-projects/OmniTAK-Android@d1569ae`](https://github.com/engindearing-projects/OmniTAK-Android/tree/d1569ae313d655f6244f1c3e92442a5bb1e90846) (upstream `main` at fork creation). This is a **source assessment**, not a claim that the radio prototype exists. Fork history and `LICENSE` retain the upstream Apache-2.0 attribution. The working fork has a different application ID and can install alongside upstream; Android will not migrate upstream's app-private preferences/certificates into the fork automatically.

## Dependency boundaries

| Area | Existing owner / entry point | Radio decision |
| --- | --- | --- |
| TAK sockets, TLS/mTLS and reconnect | `data/TAKConnection.kt`, `data/net/TakTls.kt`, `data/CertVault.kt`, `domain/ServerManager.kt` / `ReconnectSupervisor.kt` | **Keep.** `ServerManager` opens one connection per enabled server, routes inbound frames and reconnects independently of the map. Preserve identity and certificate handling and test against a TAK endpoint. |
| CoT and contacts | `data/CoTParser.kt`, `data/CoTEvent.kt`, `domain/ContactStore.kt` | **Keep, adapt presentation.** `CoTEvent` already has lat/lon/hae/ce/le, callsign, team, heading and `receivedAtMs`; `ContactStore` is a `StateFlow` keyed by UID rather than a MapLibre marker. Exclude dropped points/bookmarks from communicable peers, not all position-bearing events. |
| Chat | `data/ChatXml.kt`, `domain/ChatStore.kt`, `ui/screens/ChatScreen.kt` | **Keep wire/store; move outbound composition** out of the UI when replacing the screen. `ChatScreen.sendChatInner` currently selects server vs mesh and scopes direct messages to their source server. Don't regress GeoChat routing or self UID. |
| Own position | `data/LocationProvider.kt`, `domain/{RadioLocationSession,SelfPositionBroadcaster}.kt`, `OmniTAKApp.kt` | **Keep and validate GPS lifecycle.** GPS startup now belongs to the visible Activity or an elevated location-type foreground service, not `MapScreen`; a dataSync-only fallback cannot claim screen-off GPS. The application-level broadcaster still suppresses restored-only fixes. This is a source change, not yet an XP5 screen-off validation. |
| Foreground operation | `domain/TAKConnectionService.kt`, `OmniTAKApp.kt`, `MainActivity.kt` | **Adapt, do not replace blindly.** The service carries foreground privilege, whereas `ServerManager` owns sockets in application scope. The service contains explicit Android 15 `dataSync` timeout, location-type and start/stop race handling. `MainActivity` reconnects on resume; it cannot be the only recovery mechanism. |
| Map UI and navigation | `ui/screens/MapScreen.kt`, `ui/components/{TacticalMap,CesiumMapView,RetainedMapView,...}.kt`, `ui/navigation/AppNav.kt` | **Replace.** `AppNav` starts at `map` and has map toolbar, radial, lasso and overlay routes. Remove the map screens and supporting UI, not merely their navigation link. Build radio-first, D-pad-focusable destinations. |
| Map data and resources | `data/{MapTileHttp,MBTilesOverlay,KmlVectorOverlay,RasterOverlay,Drawing}.kt`, `data/offline/`, `domain/{DrawingStore,MapCameraStore,LocalMarkerStore,LassoSelectionService}.kt`, `assets/cesium_scene.html` and symbol assets | **Remove after reference audit.** `GeoMath.kt` is reusable without a renderer; preserve relative location calculations. Keep persistent position and TAK protocol fields even if map styles/camera/tiles are removed. |
| Plugin layer | `plugins/plugin-sdk`, `plugins/example-adsb`, `plugins/example-diagnostics`, `ui/plugin/AppPluginHost.kt` | **Decouple or retire.** ADS-B declares its *own* MapLibre dependency and the SDK/host expose map overlay/radial hooks. Dropping only `:app`'s MapLibre line will not remove the runtime dependency. Retain genuinely non-map CoT hooks only if needed by the radio product. |
| Onboarding/configuration | `ui/onboarding/OnboardingFlow.kt`, `ui/screens/{AddServerScreen,EnrollServerScreen}.kt`, `domain/DataPackageBootstrap.kt`, `data/{TAKServerStore,ConfigProfileStore,SecureCredentialStore}.kt` | **Replace touch assumptions, reuse stores.** First-run onboarding uses Compose buttons without an audited focus order; certificate selection uses `OpenDocument`, and QR enrollment assumes a camera. The TAK ZIP import folder can support admin provisioning, but ZIP parsing currently uses unbounded `readBytes()` and needs limits before accepting untrusted packages. QR profiles omit cert/private secrets intentionally and are not complete deployment packages. |

Direct map-type imports appear in `data/symbology/MilStdIconCache.kt`, `data/MapTileHttp.kt`, many `ui/components/` files and `plugins/example-adsb/`. `app/build.gradle.kts` brings in MapLibre, map-only OkHttp tile override, TIFF/SVG/image libraries, 3D/Cesium assets, UAS/video and camera dependencies. **Inspect usages before pruning** any library that might serve non-map configuration or TAK flows; `settings.gradle.kts` includes both map-related plugin modules. In the current build, `UserPrefs` and `ConfigProfile` still serialize map options: drop the UI first, then remove persisted fields with tolerant decoding/compatibility tests rather than breaking old configurations.

## Minimum path to the prototype

1. Compile the fork unchanged except identity; capture baseline build/test and preserve certificate/CoT regression tests.
2. Introduce a radio-first navigation shell and remove MapLibre/Cesium, map-only plugins, map UI and map data as dependency edges are eliminated. Gate on a built APK, no map renderer runtime dependency, and TAK/CoT/PLI integration tests.
3. Define app-owned preset/channel state and logical hardware actions. Capture XP5 model/Android build and real D-pad/PTT/selector events before implementing the `SonimXP5` mapping; do **not** assume XP5plus uses the same events. Handle relative and absolute selectors, jitter/debounce and channel changes queued during held PTT. PTT is non-transmitting in the first prototype.
4. Build first-run setup, radio home, channels, contacts, messages/canned replies, relative location, status and settings with deterministic D-pad/Select/Back focus. Test real Android permissions and text-entry flows on a non-touch XP5, not just Compose previews.
5. Move GPS start/stop to permission-aware app/service ownership, persist selected channel, and announce changes locally. With the XP5 screen off, verify real knob input changes channel and causes a spoken or tone announcement while TAK connectivity, inbound chat and fresh PLI continue. Simulation alone does **not** satisfy this device gate. Investigate documented Sonim background input integration if ordinary events are unavailable.

First prototype does **not** include a voice transport or live PTT; these follow a validated screen-off radio foundation. TAK groups, voice destinations and Meshtastic channels are different concepts and must not be equated by preset selection.

## Baseline verification / outstanding risks

- Fork is a true GitHub fork with full upstream history; original empty private repository was preserved under `omnitak-radio-pre-fork`. The fork is **public**. Never commit field configuration, credentials, certificates or proprietary Sonim integrations.
- This machine has Java **26**, no installed JDK **17**, Android SDK or `adb`. Running `./gradlew :app:assembleDebug :app:testDebugUnitTest --no-daemon` still fails at Gradle startup with `26.0.1`, before Android compilation/tests. The fork's [first JDK 17 CI run](https://github.com/ivan-lambda-consulting/omnitak-radio/actions/runs/41890412060) passed the identity-only baseline; [run 41894534048](https://github.com/ivan-lambda-consulting/omnitak-radio/actions/runs/41894534048) passed `assembleDebug` and `testDebugUnitTest` including the GPS lifecycle and loopback TAK tests at `135998e`. Follow-up fixes made after that commit still require CI. No mapless APK or XP5 result is claimed yet. Device and mTLS integration gates remain **not verified** until a toolchain, test TAK endpoint and XP5 are available.
- Distinct app ID is `com.ivanlambdaconsulting.omnitakradio` while Kotlin namespace remains `soy.engindearing.omnitak.mobile`; manifest component class names must be fully qualified. `versionCode` starts at 1 for the new package. Upstream users must separately provision this app rather than expecting private data to migrate.
- Monitor Android foreground-service start restrictions, location permission denial, Android 15 service time limits, process death, user-notification visibility and device-specific knob/PTT delivery. A green desktop unit-test suite is **not** evidence of screen-off hardware support.
- **Open safety gap (`omnitak-radio-eg8`):** stopping fused updates does not clear the last in-memory *live* fix. The broadcaster currently can re-stamp that old fix as new PLI after GPS privilege is lost. Screen-off acceptance is blocked on a tested freshness/availability gate; the new location owner alone does not establish that property.
